# 📘 Day 05 Notes — Databases (SQL vs NoSQL)

## 1. What is Data in System Design?

Data is the **most valuable part** of any system.
System design focuses on:

- How data is stored
- How fast it is accessed
- How safe it remains

---

## 2. SQL Databases Explained Simply

SQL databases:

- Store data in tables
- Enforce structure
- Maintain strong consistency

### Example

User Table:

- id
- name
- email

Each row follows the same structure.

### Why Beginners Love SQL

- Predictable
- Easy to query
- Easy to explain in interviews

---

## 3. NoSQL Databases Explained Simply

NoSQL databases:

- Store data in flexible formats
- Don’t force same structure
- Scale easily

### Example

User Document:

- name
- email
- optional fields

Each record can look different.

---

## 4. SQL vs NoSQL — Real Thinking

Ask these questions:

1. Is data structured?
2. Are relationships important?
3. Will scale explode early?

If **YES to structure → SQL**  
If **YES to scale/flexibility → NoSQL**

---

## 5. Interview Safety Tip 🧠

Never say:

> “NoSQL replaces SQL”

Say instead:

> “They solve different problems”

This shows maturity.

---

## 6. Common Beginner Mistakes

❌ Choosing NoSQL just because it sounds advanced  
❌ Ignoring data relationships  
❌ Overthinking scale on Day 1 apps

---

## 7. One-Line Memory Hook

- SQL = structure + consistency
- NoSQL = flexibility + scale
